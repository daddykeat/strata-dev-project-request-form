F2 · Task and Data Plan

Each row documents and justifies a value collected by the project request form.

Visible label / question Why necessary now? Required? Native control/type Submitted name/value Autocomplete/inputmode Constraint/instruction Sensitivity and minimization decision
Name Needed to identify the person making the project inquiry and address them when responding. Yes <input type="text"> name="name" autocomplete="name" minlength="2" — Enter at least 2 characters. Personal information. Collect only the name needed to identify and respond to the client; no additional identity information is needed.
Email Provides a way to respond to the inquiry when email is the preferred contact method and provides a reliable contact option for project communication. Yes <input type="email"> name="email" autocomplete="email" inputmode="email" Enter a valid email address. Personal contact information. Use only for responding to the project inquiry and related communication.
Preferred contact method Needed to know whether the client wants project communication by email, phone, or text. Yes <fieldset> with radio buttons name="contact_method"; values="email", "phone", "text" N/A Choose one: Email, Phone, or Text. Low sensitivity. Collect only the communication preference needed to contact the client appropriately.
Phone number Needed only when the client selects phone or text as the preferred contact method. No <input type="tel"> name="phone" autocomplete="tel" inputmode="tel" Provide a phone number if you prefer to be contacted by phone or text. Personal contact information. Keep optional and collect it only when needed for the client's selected contact method.
Project type Identifies the type of work being requested so the inquiry can be evaluated and the appropriate service can be discussed. Yes <select> name="project_type"; value corresponds to selected project category N/A Select the project type that best matches your request. Low sensitivity. Limit choices to service categories relevant to the work offered.
Project description Provides the project requirements and goals needed to understand the request and determine the appropriate next steps. Yes <textarea> name="project_description" N/A maxlength="750" — Maximum 750 characters. May contain information supplied by the client. Ask only for project-relevant details and discourage unnecessary personal or sensitive information.
Budget range Helps determine whether the requested project scope can be completed within the client's available budget. No <select> name="budget"; value corresponds to selected budget range N/A Select an approximate range; exact financial information is not needed. Financially sensitive. Keep optional and request only broad ranges rather than exact income, account, or payment information.
Target timeline / launch date Needed to determine whether the requested project can be completed within the client's schedule. No <input type="date"> name="target_date" N/A Enter a target date if the project has a deadline or planned launch. No dynamic minimum date is enforced in this HTML/CSS-only prototype. Low sensitivity. Collect only the target project date and no unrelated scheduling information.
Consent to be contacted Confirms that the client agrees to be contacted using the information submitted in order to discuss this project inquiry. Yes <input type="checkbox"> name="contact_consent" value="yes" N/A I agree to be contacted about this project inquiry. Records communication consent. Limit the consent to this inquiry and related project communication rather than unrelated marketing.
